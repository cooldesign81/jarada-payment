# 구글 시트 매출 기록 연동 설정

결제 매니저에서 결제 체크가 바뀔 때마다 이번 주 결제 완료 내역을 구글 시트에 자동으로 기록하는 기능입니다.
시트는 구글 계정에서 직접 만들어야 하므로 아래 순서대로 한 번만 설정하면 됩니다. (시트 하나당 약 10분)

## 구성: 원별 시트 + 대표 시트

시트를 여러 개 등록하면 **같은 내용이 모두에 기록**됩니다. 권장 구성은 다음과 같습니다.

| 시트 | 만드는 계정 | 들어오는 기록 | 스크립트 속성 `CENTERS` |
|---|---|---|---|
| 안양평촌원 시트 | 안양평촌원 구글 계정 | 안양평촌원만 | `안양평촌원` |
| 서초반포원 시트 | 서초반포원 구글 계정 | 서초반포원만 | `서초반포원` |
| 강남대치원 시트 | 강남대치원 구글 계정 | 강남대치원만 | `강남대치원` |
| 대표 시트 | 대표 구글 계정 | 세 원 모두 | (비워 둠) |

- 각 원의 결제 매니저 설정에는 **① 자기 원 시트**와 **② 대표 시트** 두 줄을 넣습니다. 결제를 체크하면 두 시트에 동시에 기록됩니다.
- 대표 시트의 "매출기록" 탭에는 `원` 열로 세 원이 구분되고, "일별합계" 탭은 날짜·원별로 집계됩니다.
- `CENTERS` 속성을 원별 시트에 적어 두면, 설정을 잘못 붙여 넣어 다른 원의 기록이 섞이는 실수를 시트 쪽에서 막아 줍니다.
- 시트는 두 개가 아니어도 됩니다. 한 곳만 쓰거나 "+ 시트 추가"로 더 넣어도 됩니다.

## 동작 방식

- 결제 매니저가 **이번 주(원 + 주차)의 결제 완료 행을 통째로** 등록된 모든 시트 웹앱에 보냅니다.
- 시트는 `기록키`(원 | 주차 | 학생) 기준으로 같은 기록은 **갱신**, 새 기록은 **추가**, 이번에 안 온 기록(결제 체크를 해제한 경우)은 **삭제**합니다.
- 다른 원이나 지난 주의 행은 건드리지 않으므로 주가 바뀌어도 기록이 계속 쌓입니다.
- 매출 요약과 마찬가지로 **신규생 분류 결제는 기록되지 않습니다.**
- "매출기록" 탭은 결제 1건당 1행, "일별합계" 탭은 날짜·원별 합계입니다.

---

아래 1~5단계를 **시트마다** (원별 시트는 그 원의 구글 계정으로, 대표 시트는 대표 계정으로 로그인해서) 반복합니다.

## 1. 구글 시트 만들기

[sheets.google.com](https://sheets.google.com)에서 새 스프레드시트를 만들고 이름을 정합니다. (예: `자라다 매출기록 서초반포원`, 대표 계정은 `자라다 매출기록 전체`)

## 2. Apps Script 넣기

1. 시트 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 편집기에 기본으로 들어 있는 `function myFunction() {}` 코드를 모두 지우고, 이 폴더의 [`Code.gs`](./Code.gs) 내용을 전부 붙여넣습니다.
3. 위쪽 프로젝트 이름(제목 없는 프로젝트)을 눌러 이름을 정하고(예: `자라다 매출기록`), 저장(💾) 합니다.

## 3. 스크립트 속성 정하기

1. 왼쪽 메뉴 **프로젝트 설정(⚙)** → 아래쪽 **스크립트 속성** → **스크립트 속성 추가**
2. 속성 `TOKEN`, 값은 임의의 긴 문자열 (예: `jarada-2026-xk93m2p`). 아무나 시트에 행을 쓰지 못하게 막는 암호이며, 6단계에서 결제 매니저에도 똑같이 입력합니다. 시트마다 다른 값을 써도 됩니다.
3. **원별 시트라면** 속성 `CENTERS`를 하나 더 추가하고 값에 그 원 이름을 정확히 적습니다. (`안양평촌원` / `서초반포원` / `강남대치원` 중 하나) **대표 시트는 `CENTERS`를 만들지 않습니다.**
4. **저장**

## 4. 웹앱으로 배포하기

1. 오른쪽 위 **배포 → 새 배포**
2. 왼쪽 톱니(⚙)에서 유형 **웹 앱** 선택
3. 설정
   - 설명: 아무거나 (예: `v1`)
   - **다음 사용자 인증 정보로 실행: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자** ← 중요. "Google 계정이 있는 모든 사용자"가 아니라 **모든 사용자**여야 결제 매니저에서 접근할 수 있습니다.
4. **배포** → 권한 승인 창이 뜨면 계정 선택 → "확인되지 않은 앱" 경고가 나오면 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음)** → **허용**
5. 표시되는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해 둡니다. 시트마다 URL이 다릅니다.

## 5. 일별합계 자동 갱신 (선택)

매일 밤 "일별합계" 탭을 다시 계산하게 합니다.

1. 왼쪽 메뉴 **트리거(⏰)** → **트리거 추가**
2. 실행할 함수: `rebuildDailySummary`, 이벤트 소스: **시간 기반**, 트리거 유형: **일 단위 타이머**, 시간: **오후 11시~자정** → **저장**

트리거 없이도 시트 메뉴 **자라다 결제 → 일별합계 다시 만들기**로 언제든 수동 갱신할 수 있습니다. (메뉴는 시트를 새로고침하면 나타납니다.)

## 6. 결제 매니저에 연결하기

**원마다** 그 원 계정으로 로그인해서 설정합니다. 관리자 계정은 화면 상단의 원 전환 메뉴로 세 원을 차례로 설정할 수 있습니다.

1. 결제 매니저 → 상단 **⚙ 설정** → 맨 아래 **구글 시트 연동**
2. 첫 줄 "우리 원 시트"에 그 원 시트의 **웹앱 URL**과 **토큰**을 입력
3. 둘째 줄 "대표 시트"에 대표 시트의 **웹앱 URL**과 **토큰**을 입력 (세 원 모두 같은 값)
4. 각 줄의 **연결 테스트**를 눌러 "✅ 연결 성공 · (시트 이름) · 허용 원: …"이 뜨는지 확인. 원별 시트는 허용 원에 그 원 이름이, 대표 시트는 "전체"가 보여야 합니다.
5. **저장**

줄 이름은 자유롭게 바꿔도 되고, 필요 없는 줄은 ✕로 지우거나 URL을 비워 두면 저장되지 않습니다.

## 7. 확인하기

1. 명단에서 아무 학생이나 **결제** 체크 → 4초쯤 뒤 매출 요약 카드 맨 아래에 "구글 시트 기록 완료 · 시각 · N건 → 우리 원 시트, 대표 시트"가 표시됩니다.
2. 두 시트의 **매출기록** 탭에 같은 행이 생겼는지 확인합니다.
3. 체크를 해제하면 그 행이 두 시트에서 모두 사라집니다.
4. 한 시트만 실패하면 "구글 시트 일부 실패 · … · 대표 시트 ✗ (이유)"처럼 어느 시트가 왜 실패했는지 표시됩니다. 성공한 시트에는 정상 기록됩니다.
5. 매출 요약의 **📊 구글 시트에 기록** 버튼을 누르면 즉시 모든 시트에 보냅니다. (자동 기록을 꺼 둔 경우 이 버튼으로만 기록됩니다.)

## 시트 열 설명

**매출기록** 탭

| 열 | 내용 |
|---|---|
| 기록키 | `원\|주차\|구분:ID` — 갱신·삭제 기준. 수정하지 마세요 |
| 원 | 안양평촌원 / 서초반포원 / 강남대치원 |
| 주차 | 그 주의 토요일 날짜 (결제 매니저의 주차 기준) |
| 구분 | 정규(명단 학생) / 기타(신규생·기타 결제자 카드) / 상자(연구원 상자) |
| 분류 | 기타 결제자의 분류 (샘플 후 등록, 다른 요일, 기타) |
| 체크일 ~ 다음텀 | CSV 내보내기와 같은 내용 |
| 마지막갱신 | 이 행이 마지막으로 기록된 시각 |

**일별합계** 탭: 날짜, 원, 결제 건수, 합계, 카드, 이체, 제로페이, 현금, 갱신시각

## 코드를 고친 뒤에는

`Code.gs`를 수정했다면 시트마다 **배포 → 배포 관리 → 연필(✏) → 버전: 새 버전 → 배포**로 올려야 반영됩니다. 이렇게 하면 URL이 유지됩니다. "새 배포"로 만들면 URL이 바뀌어 결제 매니저 설정도 바꿔야 합니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 연결 실패: HTTP 401 / 403 / 404 | 4단계 액세스 권한이 **모든 사용자**인지, URL이 `/exec`로 끝나는지 |
| 토큰이 일치하지 않아요 | 그 시트의 스크립트 속성 `TOKEN` 값과 결제 매니저의 그 줄 토큰이 같은지 (앞뒤 공백 포함) |
| 이 시트는 ○○원 전용이에요 | 다른 원의 시트 URL을 붙여 넣었거나, `CENTERS` 값의 원 이름이 틀렸는지 |
| 응답 형식 오류 | 코드 수정 후 새 버전으로 재배포했는지, 붙여넣은 코드가 잘렸는지 |
| 기록은 되는데 시트가 비어 있음 | `SPREADSHEET_ID` 속성을 넣었다면 그 ID의 시트를 보고 있는지 |
| 체크일이 `2026. 10. 3` 처럼 날짜로 바뀜 | 탭을 직접 만들었을 때 생길 수 있음. 탭을 지우고 다시 기록하면 텍스트 서식으로 다시 만들어짐 |

## 보안 메모

- 웹앱 URL과 토큰은 Firestore의 원별 설정에만 저장되고, 공개 저장소의 `index.html`에는 들어가지 않습니다.
- 토큰은 "시트에 행을 쓰는 권한"만 보호합니다. 시트 자체의 열람 권한은 구글 시트 공유 설정으로 관리하세요. 원별 시트는 그 원 계정만, 대표 시트는 대표 계정만 열람하도록 두면 됩니다.
- 시트에는 학생 이름·나이·교사·결제 정보가 기록되므로 공유 범위를 필요한 사람으로 제한하세요.
